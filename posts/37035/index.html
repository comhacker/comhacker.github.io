临界区与互斥体

发表于 2025-08-17 更新于 2025-08-27

临界区：

当多个线程需要操作同一个变量时，会出现时间上的错误。这个共享变量称为临界资源，对共享资源的操作称为临界区。因此当访问临界资源时，需要使用资源锁，以确保同时只能有一个线程在对此资源进行访问。

死锁：

当两个或多个线程持有资源且互相等待对方持有的资源时，各线程均无法满足条件，如果都不主动释放资源，那么线程将会进入死锁状态。线程死锁会导致进程卡死，而进程死锁则可能导致操作系统死机。因此，使用多线程时应尽量避免死锁，防止程序崩溃。

死锁的预防：

死锁形成的四个条件：

  1. 互斥
  2. 不可剥夺
  3. 请求并保持
  4. 循环等待

破坏互斥条件：增加资源数

破坏不可剥夺：资源得不到满足后强行释放线程占有的资源

破坏请求和保持：预先分配（类似于银行家算法）

破坏循环等待：资源编号，顺序分配

互斥体：

互斥体（Mutual Exclusion Object，简称 Mutex） 是一种内核对象。

它的作用：保证在同一时刻，只有一个线程（或进程）能够访问某个共享资源。

它的特点：

  • 可以在 同一进程内 的多个线程间使用。
  • 也可以在 不同进程之间 使用（互斥体是 内核对象，可命名并跨进程共享）。
  • 属于 内核级同步机制，比临界区 (Critical Section) 慢一些，但更通用。

3、请求进入（等待互斥体）

内核对象有两种状态，信号状态和无信号状态。对于不同的内核对象，两种状态的转换并不相同：

  • 线程 (Thread)： 线程存活时为无信号状态，线程结束（包括正常退出、异常终止）时变为有信号状态。
  • 进程 (Process)： 进程存活时为无信号状态，进程结束时变为有信号状态。
  • 互斥量 (Mutex)： 当该互斥量不被任何线程拥有（即被释放）时变为有信号状态。WaitForSingleObject成功获取互斥量后，调用线程会成为其所有者，互斥量变为无信号状态。
  • 事件 (Event)： 通过 SetEvent函数显式将其置为有信号状态。手动重置事件 (CreateEvent(..., TRUE, ...)) 需要显式调用 ResetEvent才能重置为无信号；自动重置事件 (CreateEvent(..., FALSE, ...)) 在唤醒一个等待线程后会自动重置为无信号。
  • 信号量 (Semaphore)： 信号量计数大于 0 时为有信号状态。WaitForSingleObject成功获取信号量后，计数减 1。当计数减为 0 时，信号量变为无信号状态。

等待互斥体，这里有两种做法：

WaitForSingleObject函数：

此函数会先阻塞本线程，然后在dwMilliseconds时间内持续检测目标对象的状态，直到目标对象变为信号状态。在目标对象变为信号状态后，被阻塞的线程会恢复执行；如果对象是互斥体，那么它还会将目标对象变为无信号状态，阻止其他线程进入。

函数返回值：

  • WAIT_OBJECT_0(0) ：等待对象变为已通知
  • WAIT_TIMEOUT(0x102) ：超时

WaitForMultipleObjects函数：

作用：等待多个内核对象的已通知状态

返回值：

  • WAIT_OBJECT_0(0) ：bWaitAll为true时代表至少一个对象变为了信号状态；bWaitAll为false时代表所有对象均变为了信号状态
  • WAIT_TIMEOUT(0x102) ：超时

临界区与互斥体的区别：

特性 临界区 (CRITICAL_SECTION) 互斥体 (Mutex)
作用范围 同一进程 可跨进程
开销 低（用户态） 高（内核态）
内核对象 否 是
是否可命名 否 可以命名（CreateMutex 传名字）
性能 高 低
等待时间 一直等待 可设置等待时间
是否需要清理 需使用DeleteCriticalSection函数清理 系统自动清理

建议同一进程间的同步时使用临界区；跨进程时使用互斥体。
