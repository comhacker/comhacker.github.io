固件

发表于 2025-11-23 更新于 2025-11-24

什么是固件

固件是被写入设备内部的存储芯片里面的一种软件，用来控制设备最核心、最基础的功能。它是设备的大脑，与硬件紧密绑定，且通常不会发生改变，因此被称为固件。

固件有如下任务：

  1. 初始化硬件。
  2. 提供最基础的硬件功能。
  3. 与驱动程序进行交流

例如：

  • 键盘的固件：决定按键逻辑、灯光效果
  • U盘的固件：负责读写管理、磨损均衡、坏块检测
  • 路由器固件：控制 Wi-Fi、网络转发
  • 手机固件：触摸响应、开机启动等

固件的定位

将整个设备的软件进行层级划分：

🏢 应用程序（App）：
🏢 操作系统（Android / Linux / Windows）（包含了驱动程序）
🏢 驱动程序（Drivers）
🏢 固件（Firmware）
🏢 硬件（CPU / 存储 / 外设）

可以看到，固件是比操作系统还底层的软件，直接控制硬件的执行。

驱动程序是位于操作系统内部的一段软件模块，它控制操作系统与固件之间的交互，完成以下任务：

  • 告诉操作系统，这个硬件怎么用
  • 为操作系统提供硬件的接口

操作系统是硬件与软件资源的大管家，它完成以下工作：

  • 资源分配
  • 人机交互界面
  • 给应用提供统一接口，屏蔽硬件差异。例如微信不用为每个手机厂商提供版本，只需要提供一个针对操作系统的版本。为oppo、小米等厂商提供安卓版，为苹果提供IOS版，为华为提供鸿蒙版。

当用户使用拍照软件进行拍照时，操作系统、驱动、固件是这样进行协调工作的：

  1. 相机app调用摄像头api，告诉操作系统“我需要使用摄像头”
  2. 操作系统找到空闲的设备，然后告诉驱动程序“让他使用摄像头”
  3. 驱动程序根据请求，翻译为以下指令给固件：设置曝光参数->调整对焦->启动图形采集->让固件读取传感器数据
  4. 固件收到指令，直接控制硬件完成上述操作，将结果返回给驱动
  5. 驱动将结果交给操作系统，操作系统返回给app，app呈现给用户。

或者，可以这么理解：

  • 固件是硬件的“微型操作系统，只是不完全具备操作系统的功能
  • 驱动是操作系统的硬件翻译官，负责硬件适配

补：为什么显卡驱动出问题会蓝屏，而微信出问题只会自动关闭？

显卡驱动崩溃会蓝屏，而微信崩溃只会退出，是因为驱动运行在内核态，权限极高，一旦出现错误可能破坏系统的内核。内核是操作系统中最核心、最不能损坏的部分。一旦出现严重错误，为了防止文件系统和数据被毁，操作系统会选择立即停止工作（蓝屏），以保全内核的完整性。

电脑启动流程

电脑开机时，各个软件的执行流程如下：

  1. CPU上电。按下电源键，电源开始向CPU和主板供电。
  2. 找到系统固件。CPU通电后，从预设的地址处（如X86是0xFFFFFFF0）取裸指令（机器码）开始执行，这里就是系统固件（也称主板固件）的位置。
  3. 执行系统固件。旧式电脑固件采用BIOS模式，现代电脑默认采用UEFI 模式。UEFI 会完成启动CPU、初始化设备、记载文件系统等功能。它最重要的功能是运行启动引导程序（Bootloader）。
  4. 运行启动引导程序。在跳转到启动引导程序后，启动引导程序会找到操作系统内核文件位置（PE\ELF格式），对内核文件进行解析、加载，然后准备内存布局（页表），启用保护模式/长模式（即切换到32位/64位模式），跳转到内核入口函数。
  5. CPU执行内核操作码，操作系统正式启动！内核启动时，需要做很多初始化工作，包括初始化内存管理、初始化进程管理器、加载硬件驱动、启动第一个用户态进程。
  6. 启动用户空间。此时操作系统启动用户态进程：如Windows的smss.exe（会话管理）、Winlogon.exe（登录界面）、explorer.exe（桌面）等，这是用户真正能感受到的进程。

注：启动引导程序与驱动程序不同，他们有以下区别：

  • 启动引导程序的工作是完成操作系统启动前的准备工作及引导操作系统的启动，驱动程序的工作是协助操作系统与硬件进行交互
  • 启动引导程序算一个独立的可执行程序，驱动程序属于操作系统内部
  • 启动引导程序工作在操作系统启动前，而驱动程序只在操作系统启动后由操作系统加载和管理

规范

UEFI 规范：

UEFI规范是在电脑主板的固件需要遵守的规范，它由UEFI Forum 制定。UEFI Forum 是一个行业联盟组织，成员包括微软、intel、lenovo、ARM、AMD等。

整个PC行业的主板商都需要严格按照这个规范写主板固件，并且，他们不需要关注上层操作系统的实现。

  • UEFI 要求 Bootloader 是 EFI 格式
  • UEFI 要求入口点是某个机器码标准（如0xFFFFFFF0）

CPU指令集规范：

这个规范是由CPU供应商制定。目前的主流是x86、x86-64和ARM指令集。

  • x86由Intel开发
  • AMD扩展了X86，制作了AMD64。intel采用了AMD64，形成行业统一的X86-64
  • ARM由ARM公司开发，是一个精简指令集

CPU的指令集是电脑最底层的东西，不同的指令集，意味着所有上层的实现细节不同，但是总体逻辑架构是相同的

CPU启动协议：

规定了CPU上电后从哪个固定地址（复位向量）开始取第一条指令，这是硬件到固件的唯一桥梁。这个协议是CPU架构本身的一部分，不同 CPU 架构（如 x86, ARM）有各自不同的复位向量地址。UEFI固件必须安置在该地址或该地址指向的位置。

  • 可以得出以下结论：
  • 主板必须遵守UEFI规范
  • UEFI固件必须安置在CPU启动协议规定的位置
  • CPU必须遵守CPU架构（CPU指令集规范和CPU启动协议）
  • 操作系统必须兼容CPU架构和UEFI规范
  • 操作系统适配硬件，而不是硬件适配操作系统

逆向固件

固件的逆向一般使用binwalk，这个工具在kali中自带，在linux中可通过命令安装

Binwalk是一个分析二进制文件（尤其是固件）的工具，它可以

  • 自动识别文件系统、压缩包、图片等常见数据结构
  • 扫描固件并提取其中的文件
  • 分析固件的打包结构
  • 查看是否存在嵌套压缩、固件格式等

执行指令时建议是以root身份来打开的虚拟机，规避权限问题。
