汇编里面实现随机可通过rdtsc指令。这个指令用于读取cpu内部的64位时间戳计数器，读出的64 位值的高32位放在edx里面，而低32位放在eax里面。我们需要的ID范围非常有限，只需要在0~12之间即可，故可仅使用edx和eax寄存器其中之一当作随机数就行。

仅仅得到随机数不够，还需要对随机数进行束缚，令其严格落在0~12之间，一旦出界，那么很可能会导致程序直接崩溃！！！

由于这段代码要经常执行，而除法在计算机中执行很慢，且可能会出现除0错误。于是，我这里采用了优化，即通过乘法和移位实现高效束缚。

32位寄存器能存储的最大值为0xFFFF，最小值为0x0，两个32位数相乘得到的值为64位。假如让一个随机的32位数乘以0xD（也就是十进制12），那么积的最大值就是0xFFFF*0xD=0xC FFF3，最小值就是0x0。如果令积右移32位，那么得到的值最大为0xC，最小为0x0，这样就达到了限制随机数的目标。

汇编里面乘法的实现用到了mul指令。这个指令默认的乘数之一在eax里面，而mul后面跟着的是另一个乘数。它的积放在EDX:EAX寄存器对中，取edx寄存器的值就相当于对积进行了32位右移。

全屏秒杀

分析：

僵尸结构体里面有一个字段存储僵尸状态，当僵尸处于不同的状态时，他的外观也会不同。比如撑杆僵尸，拿着杆子、撑杆跳起、无杆子时是3个不同状态；铁桶僵尸，有铁桶和无铁桶也是不同状态。当僵尸死亡时，又是另一个状态。我们可以通过修改僵尸状态ID来让僵尸死亡。

第一步，先找僵尸状态ID。先种下一个撑杆僵尸，然后搜索未知的初始值，筛选值小于200大于0，然后种下植物，当僵尸起跳时，搜索变化的值。僵尸没杆子后又搜索变化的值。然后把僵尸杀死，重新种一个撑杆僵尸，搜索未变的初始值（对比首次扫描）。重复操作直到找到唯一的值。可以发现，撑杆僵尸有杆时是11，起跳是12，无杆是13。当僵尸死亡后，其ID变为1。那么，是不是意味着如果ID为1，那么僵尸处于死亡状态呢？我们可以通过修改状态ID来试着看僵尸会变成什么样。结果发现，当状态改为1时，僵尸会直接消失；当状态改为3时，僵尸会立即死亡。那就意味着其实僵尸在死亡时的状态其实是3，只不过在死亡后状态立马变为1，然后消失，这个过程非常快，我们看不到。

第六关：指针

理论：

我们知道，存储变量可通过3种方式：

  1. 全局变量存储。全局变量对于整个程序有效，且RVA在编译后就已经确定了（绝对地址），不会在每次程序打开时改变
  2. malloc分配。malloc从堆里面分配内存，每一次分配的都是随机的地址
  3. 局部变量存储。局部变量是函数定义的变量，使用的是栈存储，在函数执行完成后自动释放，不可用于其他函数。

像血量这样的数值，大多数时候都要被多个函数访问，如果使用局部变量存储，那么每次函数调用时都要将血量作为参数传入，函数十分臃肿。因此第3种方法几乎不会被用来存储这样的值。如果采用malloc分配，则需要使用一个全局变量来存储返回的指针，其他函数通过这个指针来访问血量，绝大多数程序都是采用这个方式。这个全局变量的地址在编译时就已经确定，每一次程序运行都不会改变，我们称之为“基址”，这种地址在CE里面使用绿色字体来标识。而其他的地址都是动态地址，每一次运行可能会不同，在CE里面使用黑色字体来标识。

CE锁血的本质是持续监视并修改特定内存地址的值，使其保持在一个固定值。如果直接锁血动态地址（如malloc返回的地址），由于每次程序运行该地址都变化，锁血会失败。正确的方法是锁血通过基址和指针链找到的最终地址。基址（全局变量的地址）是固定的，CE每次运行都会从基址开始，跟随指针链找到当前的血量地址（动态地址），然后锁血该地址的值。更直白一点：

看这段代码，我指的第一种锁血（动态地址锁血）就是对malloc返回的地址进行锁血（事实上，通过数值扫描找到的第一个地址也就是这个地址），这个地址在每一次程序执行时都会改变，因此这个锁血是失败的。而第二种锁血（基址锁血），锁的其实是全局变量里面存储的地址，这个地址虽然每一次运行都会变动，但是CE每一次锁血时，都是通过这个指针链来查找的，找到的是更新后的地址，锁血因此是成功的。我们此关就是要通过动态地址来往上找，直到找到基址，然后构建指针链，让CE每次通过这个指针链找到血量，进行锁血。

快速幂算法

引入：

首先，考虑一个简单的问题：如何计算 a 的 n 次幂，即 a^n？

最直接的方法是连乘法，也就是将 a 乘以自己 n-1 次。

  • 例如，计算 2^10，我们需要进行 9 次乘法：2 * 2 = 4, 4 * 2 = 8, ..., 一直到 512 * 2 = 1024。

这种方法的时间复杂度是 **O(n)**。当指数 n 非常巨大时（例如在密码学中，n 可能是一个几百位的大数），这个计算效率会极其低下，甚至不可行。

快速幂算法就是为了解决这个问题而诞生的，它可以将时间复杂度从 O(n) 降低到 **O(log n)**，这是一个巨大的飞跃。

核心原理：

一、折半求幂

求a的n次方，如果n是偶数，那么
$$
a^{n}=a^{n/2}::a^{n/2}:=:(a^{n/2})^{2}
$$
如果n是奇数，那么
$$
a^{n}=a^{n-1}::a:=:(a^{(n-1)/2})^{2}:*:a
$$
这意味着，可以通过递归的方式来求这个值。假设要求2的10次方：

  1. 2^10 = (2^5)^2
  2. 现在需要计算 2^5（n=5是奇数）：2^5 = (2^2)^2 * 2
  3. 现在需要计算 2^2（n=2是偶数）：2^2 = (2^1)^2
  4. 现在需要计算 2^1（n=1是奇数）：2^1 = (2^0)^2 * 2
  5. 2^0 = 1（递归基/终止条件）

然后回溯：

  1. 2^1 = (1)^2 * 2 = 2
  2. 2^2 = (2)^2 = 4
  3. 2^5 = (4)^2 * 2 = 16 * 2 = 32
  4. 2^10 = (32)^2 = 1024

二、二进制求幂

任何一个数都可等价于多个2的幂相加，例如10=2^3+2^1=8+2，那么a^10 = a^(8+2) = a^8 * a^2。10的二进制形式是1010，由此可知，a^n 的值等于**n 的二进制位所有为 1 的位置所对应的 a^(2^k) 的乘积**，而每一个a的幂可以通过折半法求得。例如：

  1. 二进制数1010每一位对应的幂值分别为8、4、2、1
  2. 其中从低位到高位的第2位和第4位是1，那么求2^10可转化为求(2^8)*(2^2)
  3. 折半求幂：2^8 = (2^4)^2
  4. 2^4 = (2^2)^2
  5. 2^2 = (2^1)^2
  6. 2^1 = (2^0)*2
  7. 2^0 = 1
  8. 开始回溯：2^1 = 2, 2^2 = 4, 2^3 = 8, 2^4 = 16, 2^8 = 256。
  9. 求积 2^10 = 256 * 4 = 1024

模拟键击

先理清两个概念：扫描码与虚拟键码。

扫描码与虚拟键码：

  • 扫描码：物理键盘中每一个按键都对应一个编码，称为扫描码。当物理键盘中某个按键被按下时，键盘会通过USB发送被按下的按键对应的扫描码给电脑操作系统。扫描码实际上是向操作系统说明，是左起第某排第某个键被按下。
  • 虚拟键码：是由操作系统抽象出来的、与某个按键绑定的键值。例如，0x31代表键盘“1”键。这个虚拟键码表与键盘布局、输入法、当前语言环境相关。当操作系统收到键盘发出的扫描码时，会根据当前环境的【扫描码-虚拟键码对应表】来将扫描码转化为对应的虚拟键码。

那么，为什么还要有扫描码这样的中间码呢？键盘直接将键帽与虚拟键码对应，然后直接发送虚拟键码给操作系统不行吗？

键盘的电路结构和按键矩阵基本是统一的，因此相同物理位置的按键会发出相同的扫描码，结构如下图所示(蓝色数字代表扫描码)：

但是，各个语言环境的键盘布局却不相同。举个例子，在美式或中文键盘里，扫描码为0x10对应的虚拟键码是0x51，代表”Q”键。而法语键盘中，扫描码为0x10对应的虚拟键码是0x41，代表”A”键。

如果操作系统不做转换，那么键盘有两种方式维持功能：

-

  1. 一个键盘只专注于一种语言环境，在敲击按键后直接发送虚拟键码而不是扫描码
  2. 转换表由键盘来维护，键盘根据当前语言环境选择转换表

这两种方式都有缺点：方法1，键盘不支持多语言输入法，没有通用性，你需要买多个不同语言的键盘来完成英文和中文输入；方法2，等于把键盘布局映射表塞进键盘硬件，破坏了硬件简洁性。因此，键盘只需发送扫描码，映射逻辑交由操作系统维护，才能保持通用性。

在应用程序中，大多数时候都忽视扫描码，而是使用虚拟键码来解释击键消息。但是，在一些情况下，扫描码被使用来规避键盘布局带来的问题。例如，在大多数游戏前后左右移动都是使用WASD四个按键，这4个按键在美式键盘中扫描码对应0x11、0x1E、0x1F、0x20，这4个按键挨在一起。但是，在法式键盘中，WASD对应的是0x2D、0x10、0x1E、0x20，这4个按键位置分散，操作手感完全不同。如果一个游戏使用虚拟键码WASD来判断玩家操作，那么对于法国玩家来说，体验感会相当不好。如果使用扫描码0x11、0x1E、0x1F、0x20来判断玩家操作，那么无论是哪种键盘布局，都是对应键盘上的那几个位置，只不过操作的不再是WASD，而是ZQSD了。

进程与线程

定义：

进程是一个具有独立功能的程序在一个数据集合上的运行过程——这是进程在教科书上的定义。这里有两个重要的部分：

  • 数据集合：进程中的内存空间、文件句柄、环境变量等系统资源。也称资源容器。
  • 运行过程：即线程。

因此，可以将进程描述为：进程 = 资源容器 + 一个或多个线程

如果没有线程，进程就是个“空壳”，不会运行；如果只有线程，没有资源容器，线程就没地方存放代码/数据/栈。

一个进程中的所有线程共享此进程中的资源容器，同时，每一个线程又把他们的代码、数据、栈和线程控制块存放在资源容器中。线程与资源容器相互配合，使得进程能顺利执行。

进程控制块and线程控制块：

进程控制块（PCB）和线程控制块（TCB）都属于内核对象，他们分别记录了进程、线程的基本信息。在Windows操作系统里面，PEB的具体实现为EPROCESS 对象，TCB的具体实现为ETHREAD 对象。

在Windows里面，使用函数创建进程或线程时，返回的句柄其实指向的是对应的PCB或TCB。

EPROCESS 对象主要记录以下几种信息：进程基本信息、内存情况、线程管理、句柄信息等。其部分字段如下：

字段名 类型 描述
UniqueProcessId HANDLE 进程 PID（进程唯一标识符），任务管理器显示的值。
InheritedFromUniqueProcessId HANDLE 父进程 PID（创建此进程的进程 PID）。
ImageFileName CHAR[16] 进程镜像文件名（如 chrome.exe），长度固定为 15字符+1终止符。
SectionBaseAddress PVOID 进程主映像（EXE 文件）在内存中的基地址。
ThreadListHead _LIST_ENTRY 线程链表头，连接该进程的所有 _ETHREAD结构。
BasePriority CHAR 进程的基础调度优先级（影响线程优先级基础值）。
ObjectTable _HANDLE_TABLE* 进程句柄表指针，管理打开的文件、互斥体、注册表键等内核对象。

ETHREAD 对象则主要聚焦在线程调度、上下文执行、栈等，其部分字段如下：

字段名 类型 描述
Cid _CLIENT_ID 线程唯一标识符： UniqueProcess（所属进程PID） ；UniqueThread（线程ID，TID）。
ThreadsProcess _EPROCESS* 指向所属进程的 EPROCESS 指针，快速定位进程上下文。
StartAddress PVOID 线程起始函数地址（用户态为 LPVOID lpStartAddress，内核态为回调入口）。
ExitStatus NTSTATUS 线程退出代码（STILL_ACTIVE表示运行中）。
BasePriority CHAR 基础优先级（继承自所属进程优先级）。
Priority CHAR 当前动态优先级（可能因I/O完成、前台切换等调整）。
Quantum CHAR 剩余时间配额（调度器递减，耗尽后暂停运行）。
InitialStack PVOID 内核栈起始地址（栈底位置）。
StackLimit PVOID 内核栈边界地址（栈顶保护区域，用于溢出检测）。
TrapFrame _KTRAP_FRAME* 中断/异常栈帧指针，保存中断发生时用户态寄存器（EIP/ESP等）。
ThreadListEntry _LIST_ENTRY 所属进程的线程链表节点： Flink指向下一线程 → Blink指向上一线程。 通过进程控制块里面的的 ThreadListHead遍历。

当发生线程调度时，调度器将当前线程的各个寄存器的值压入内核栈，然后将栈顶指针存储到线程控制块的TrapFrame字段。当下一次再调度回此线程时，调度器通过栈起始地址InitialStack和中断栈帧指针TrapFrame来寻址，然后将各寄存器出栈，这样就完成了寄存器恢复。

注：内核对象内部字段的指针所指向的数据结构或内存区域，绝大部分位于内核空间中。

进程调度or线程调度

进程是操作系统进行资源分配的基本单位。但是线程才是操作系统进行 CPU调度的基本单位。

  • 在早期的操作系统中，只支持单线程的进程，这个时候，线程几乎可以等价于进程。这个阶段，操作系统在进行CPU调度时实际操作的是进程中的主线程，但是由于是单线程，故亦可称为进程调度。
  • 在现代操作系统中，支持多线程的进程。此时，线程与进程划分清晰，操作系统在进行CPU调度时并不会管线程属于哪个进程，而是把线程视为一个独立单位进行调度。（注：这里并不是说进程不会影响线程的调度，例如线程调度的基础优先级由进程决定）

无论是哪个阶段的操作系统，实际上都没有所谓的“进程调度”，操作系统实际上进行的都是“线程调度”

进程句柄表

每个进程维护着一张句柄表，当进程里面的任何一个线程创建或打开一个内核对象时，该表都会添加一项。注意，此表是全体线程共有的资源，这也是为什么可以通过把句柄设置为全局变量让进程中的其他线程使用。句柄的值实际上是该对象在句柄表中的索引，通过索引来间接访问内核对象，实现资源保护。

终止进程：

法一：ExitProcess函数

执行步骤：

  1. 强制杀死所有线程
  2. 卸载所有DLL
  3. 内核关闭进程所有打开的句柄，释放所有资源
  4. 进程对象状态设置为已通知

优点：这个函数是终止本进程，可以选择在哪个位置终止，因此是可控的，用户机会让进程避免资源泄露。

缺点：如果某个线程持有锁但是没来得及释放，而卸载DLL的线程需要这个锁，那么可能导致死锁。因此尽量在归还资源后再调用此函数。

法二：TerminateProcess函数

此函数用于关闭其他进程。在调用后，会：

  1. 强制杀死所有线程
  2. 内核关闭进程所有打开的句柄，释放所有资源
  3. 进程对象状态设置为已通知

由于调用时无法获知进程的情况，因此这种方法很可能导致资源泄露。在实际情况中尽量不使用此函数。

继承句柄：

​ 创建进程时，如果需要让子进程继承本进程的句柄那么需要在打开句柄时选择可继承句柄和创建进程时选择继承句柄。在进程句柄表里面每一个句柄项都有一个字段Flags，这里记录了打开句柄时句柄的属性，其中有一项为是否继承。在创建进程时如果选择继承句柄，那么父进程会把其句柄表中Flags字段为继承的所有句柄项复制给子进程，同时此内核对象引用计数加一，等同于子进程打开了一个句柄。

​ 虽然句柄表里面有此内核对象的句柄了，但是子进程并不知道此句柄的值，就无法使用此句柄。因此，需要在创建进程时，将句柄的值作为参数传入，然后在子进程获取参数、转为句柄。
