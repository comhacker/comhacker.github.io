进程与线程

定义：

进程是一个具有独立功能的程序在一个数据集合上的运行过程——这是进程在教科书上的定义。这里有两个重要的部分：

  • 数据集合：进程中的内存空间、文件句柄、环境变量等系统资源。也称资源容器。
  • 运行过程：即线程。

因此，可以将进程描述为：进程 = 资源容器 + 一个或多个线程

如果没有线程，进程就是个“空壳”，不会运行；如果只有线程，没有资源容器，线程就没地方存放代码/数据/栈。

一个进程中的所有线程共享此进程中的资源容器，同时，每一个线程又把他们的代码、数据、栈和线程控制块存放在资源容器中。线程与资源容器相互配合，使得进程能顺利执行。

进程控制块and线程控制块：

进程控制块（PCB）和线程控制块（TCB）都属于内核对象，他们分别记录了进程、线程的基本信息。在Windows操作系统里面，PEB的具体实现为EPROCESS 对象，TCB的具体实现为ETHREAD 对象。

在Windows里面，使用函数创建进程或线程时，返回的句柄其实指向的是对应的PCB或TCB。

EPROCESS 对象主要记录以下几种信息：进程基本信息、内存情况、线程管理、句柄信息等。其部分字段如下：

字段名 类型 描述
UniqueProcessId HANDLE 进程 PID（进程唯一标识符），任务管理器显示的值。
InheritedFromUniqueProcessId HANDLE 父进程 PID（创建此进程的进程 PID）。
ImageFileName CHAR[16] 进程镜像文件名（如 chrome.exe），长度固定为 15字符+1终止符。
SectionBaseAddress PVOID 进程主映像（EXE 文件）在内存中的基地址。
ThreadListHead _LIST_ENTRY 线程链表头，连接该进程的所有 _ETHREAD结构。
BasePriority CHAR 进程的基础调度优先级（影响线程优先级基础值）。
ObjectTable _HANDLE_TABLE* 进程句柄表指针，管理打开的文件、互斥体、注册表键等内核对象。

ETHREAD 对象则主要聚焦在线程调度、上下文执行、栈等，其部分字段如下：

字段名 类型 描述
Cid _CLIENT_ID 线程唯一标识符： UniqueProcess（所属进程PID） ；UniqueThread（线程ID，TID）。
ThreadsProcess _EPROCESS* 指向所属进程的 EPROCESS 指针，快速定位进程上下文。
StartAddress PVOID 线程起始函数地址（用户态为 LPVOID lpStartAddress，内核态为回调入口）。
ExitStatus NTSTATUS 线程退出代码（STILL_ACTIVE表示运行中）。
BasePriority CHAR 基础优先级（继承自所属进程优先级）。
Priority CHAR 当前动态优先级（可能因I/O完成、前台切换等调整）。
Quantum CHAR 剩余时间配额（调度器递减，耗尽后暂停运行）。
InitialStack PVOID 内核栈起始地址（栈底位置）。
StackLimit PVOID 内核栈边界地址（栈顶保护区域，用于溢出检测）。
TrapFrame _KTRAP_FRAME* 中断/异常栈帧指针，保存中断发生时用户态寄存器（EIP/ESP等）。
ThreadListEntry _LIST_ENTRY 所属进程的线程链表节点： Flink指向下一线程 → Blink指向上一线程。 通过进程控制块里面的的 ThreadListHead遍历。

当发生线程调度时，调度器将当前线程的各个寄存器的值压入内核栈，然后将栈顶指针存储到线程控制块的TrapFrame字段。当下一次再调度回此线程时，调度器通过栈起始地址InitialStack和中断栈帧指针TrapFrame来寻址，然后将各寄存器出栈，这样就完成了寄存器恢复。

注：内核对象内部字段的指针所指向的数据结构或内存区域，绝大部分位于内核空间中。

进程调度or线程调度

进程是操作系统进行资源分配的基本单位。但是线程才是操作系统进行 CPU调度的基本单位。

  • 在早期的操作系统中，只支持单线程的进程，这个时候，线程几乎可以等价于进程。这个阶段，操作系统在进行CPU调度时实际操作的是进程中的主线程，但是由于是单线程，故亦可称为进程调度。
  • 在现代操作系统中，支持多线程的进程。此时，线程与进程划分清晰，操作系统在进行CPU调度时并不会管线程属于哪个进程，而是把线程视为一个独立单位进行调度。（注：这里并不是说进程不会影响线程的调度，例如线程调度的基础优先级由进程决定）

无论是哪个阶段的操作系统，实际上都没有所谓的“进程调度”，操作系统实际上进行的都是“线程调度”

进程句柄表

每个进程维护着一张句柄表，当进程里面的任何一个线程创建或打开一个内核对象时，该表都会添加一项。注意，此表是全体线程共有的资源，这也是为什么可以通过把句柄设置为全局变量让进程中的其他线程使用。句柄的值实际上是该对象在句柄表中的索引，通过索引来间接访问内核对象，实现资源保护。

Windows 内核对象位于内核地址空间，并不会用满 64 位。比如在 Windows 10/11 x64 上，虚拟地址通常只使用 低 48 位， 所以内核没必要把 64 位全存进去，省空间。而且内核对象都是以8字节对齐的，所有内核对象的起始地址都会是8的倍数，因此，在他们的地址二进制表示里，最低 3 位永远是 0。于是，这3个确定的位被用作标志位。所以，内核对象在进程中的实际地址其实是ObjectPointerBits字段左移3位。

终止进程：

法一：ExitProcess函数

执行步骤：

  1. 强制杀死所有线程
  2. 卸载所有DLL
  3. 内核关闭进程所有打开的句柄，释放所有资源
  4. 进程对象状态设置为已通知

优点：这个函数是终止本进程，可以选择在哪个位置终止，因此是可控的，用户机会让进程避免资源泄露。

缺点：如果某个线程持有锁但是没来得及释放，而卸载DLL的线程需要这个锁，那么可能导致死锁。因此尽量在归还资源后再调用此函数。

法二：TerminateProcess函数

此函数用于关闭其他进程。在调用后，会：

  1. 强制杀死所有线程
  2. 内核关闭进程所有打开的句柄，释放所有资源
  3. 进程对象状态设置为已通知

由于调用时无法获知进程的情况，因此这种方法很可能导致资源泄露。在实际情况中尽量不使用此函数。

继承句柄：

​ 创建进程时，如果需要让子进程继承本进程的句柄那么需要在打开句柄时选择可继承句柄和创建进程时选择继承句柄。在进程句柄表里面每一个句柄项都有一个字段Flags，这里记录了打开句柄时句柄的属性，其中有一项为是否继承。在创建进程时如果选择继承句柄，那么父进程会把其句柄表中Flags字段为继承的所有句柄项复制给子进程，同时此内核对象引用计数加一，等同于子进程打开了一个句柄。

​ 虽然句柄表里面有此内核对象的句柄了，但是子进程并不知道此句柄的值，就无法使用此句柄。因此，需要在创建进程时，将句柄的值作为参数传入，然后在子进程获取参数、转为句柄。

内核对象

​ “内核对象”（kernel object）指的是由 Windows 内核（NT 内核）创建和管理的、运行在内核态的数据结构。用户态的应用程序不能直接操作这些结构，需要通过 句柄 来访问和使用它们。内核对象存在于进程高2G的空间中，这里处于内核态空间，所有进程共享，这意味着这些内核对象只要创建成功，那么任何进程都可以通过句柄访问（内核空间实际上是一块物理内存，由操作系统统一管理，所谓的高2G空间只是这个物理地址在进程中的映射）。常见的内核对象有：进程、线程、互斥体、事件、信号量、文件等。

​ 内核对象由操作系统管理，不需要我们手动进行销毁。其内部常设有引用计数：

  • 当创建或打开内核对象时，该内核对象引用计数加一
  • 当关闭内核对象句柄时，该内核对象引用计数减一
  • 当引用计数为0时（即无线程或进程使用此对象），操作系统销毁此内核对象

简而言之，就是一共有多少个内核对象的句柄，引用计数就是多少；当最后一个句柄被关闭时，内核对象销毁。

特别情况：
对于动态对象，例如线程、进程等，在创建时内核就会持有对它的引用，当其执行完毕后会解除这个引用。因此，即使关闭了所有线程对此内核对象的引用，此内核对象也不会销毁。这样做是为了确保这些内核对象生命周期的完整性。

死锁：

当两个或多个线程持有资源且互相等待对方持有的资源时，各线程均无法满足条件，如果都不主动释放资源，那么线程将会进入死锁状态。线程死锁会导致进程卡死，而进程死锁则可能导致操作系统死机。因此，使用多线程时应尽量避免死锁，防止程序崩溃。

死锁现象：

如上面这个程序，线程1先申请资源B成功并等待1s，此时线程二申请资源A成功并等待1s，然后线程1等待资源A，线程2等待资源B，两个线程都无法满足条件，故进程死锁，两个线程都无法继续执行。

死锁的预防：

死锁形成的四个条件：

  1. 互斥
  2. 不可剥夺
  3. 请求并保持
  4. 循环等待

破坏互斥条件：增加资源数

破坏不可剥夺：资源得不到满足后强行释放线程占有的资源

3、请求进入（等待互斥体）

内核对象有两种状态，信号状态和无信号状态。对于不同的内核对象，两种状态的转换并不相同：

  • 线程 (Thread)： 线程存活时为无信号状态，线程结束（包括正常退出、异常终止）时变为有信号状态。
  • 进程 (Process)： 进程存活时为无信号状态，进程结束时变为有信号状态。
  • 互斥量 (Mutex)： 当该互斥量不被任何线程拥有（即被释放）时变为有信号状态。WaitForSingleObject成功获取互斥量后，调用线程会成为其所有者，互斥量变为无信号状态。
  • 事件 (Event)： 通过 SetEvent函数显式将其置为有信号状态。手动重置事件 (CreateEvent(..., TRUE, ...)) 需要显式调用 ResetEvent才能重置为无信号；自动重置事件 (CreateEvent(..., FALSE, ...)) 在唤醒一个等待线程后会自动重置为无信号。
  • 信号量 (Semaphore)： 信号量计数大于 0 时为有信号状态。WaitForSingleObject成功获取信号量后，计数减 1。当计数减为 0 时，信号量变为无信号状态。

进程与线程

​ 源码编译得到的二进制文件（PE文件）叫程序，把程序拉伸到内存中得到的是内存映像，包括代码段、数据段、堆、栈等区域，在得到足够的条件后，程序就会跑起来，程序运行的过程称为进程。在进程执行时，按固定顺序执行的执行流称为线程。一个进程之中可以有多个线程，每一个线程在运行时需要分配一个cpu，一个进程的多个线程如果都分配到cpu，那么这些线程可以同时执行。

​ 每一个进程都有其专属的4G空间，互不影响。操作系统给每个进程分配一个唯一的进程标识符，即PID，Win32提供API通过进程PID来打开进程，获取进程句柄。这里的“打开”并不是指让程序运行，而是打开此进程的访问权限，使得本进程可与此进程通信。进程句柄与进程标识符不同，进程标识符是操作系统用来标记进程的一个4字节的编号，在进程创建之时就已经确定，且在进程的生命周期内不会改变；进程句柄类似于一张通行证，在使用OpenProcess打开进程后会得到一个进程的句柄，这个句柄就是与此进程通信的通行证。当你不需要与此进程通信时，使用CloseHandle来将此通行证归还(注意：此函数只是关闭句柄，并不会关闭进程)，归还后，此句柄将不能使用。当你下次再使用OpenProcess打开此进程时，得到的句柄并不一定相同。

​ 同样，线程也有一个线程标识符，在CreateThread创建线程后会返回一个线程句柄，使用CloseHandle关闭线程句柄后并不会关闭线程。

同步与异步

同步，是指操作按顺序执行，每个操作必须等待前一个操作完成后才能开始。在同步模型中，调用方会等待被调用操作完成后才继续执行后续代码。执行流程是线性的、阻塞的。

异步，是指调用方发起操作后，不需要等待其完成，可以继续执行其他任务。异步是非线性的、并发的。

  • 同步：使用SendMessage发送消息时，如果窗口在本线程，则消息不会进消息队列，而是在发送消息后，立马在本线程调用目标窗口的回调函数，并在函数执行完后返回，继续往下执行。如果窗口不在本线程，消息会被投递到目标线程的消息队列中，并阻塞本线程直到消息被处理完成。
  • 异步：在我们对窗口进行操作时（比如拖动、点击、拉伸等），系统会生成一个消息，并把消息分发到对应窗口的消息队列中，此时，窗口并不会立即处理此消息，而是会等消息循环处理到这时再调用过程函数处理。这就是异步。使用PostMessage发送消息时也是异步。

WM_PAINT消息的特殊性

WM_PAINT消息是由系统自动生成的，故其属于异步消息。WM_PAINT消息的优先级非常低，当且仅当消息队列里面没有其他更高优先级的消息需要处理时，系统会检查是否存在无效区域，如存在，则生成一个WM_PAINT消息并放入消息队列里面（两个条件缺一不可）。

无效区域是指窗口工作区内当前被认为内容失效、过时或需要重新绘制的那部分区域，可由InvalidateRect函数指定。当调用InvalidateRect函数指定一个无效区域时，并不会立即生成WM_PAINT消息，而是会在消息队列空闲时生成。当多次调用InvalidateRect函数指定多个无效区域时，无效区域会合并，并在消息队列空闲时生成一个WM_PAINT消息。

问题分析

单线程情况：

​ 在Clock的循环里面，每次调用SetWindowText函数其内部都会使用SendMessage函数向文本框发送一个WM_SETTEXT消息（同步），然后直接调用编辑框控件的回调函数来处理，此消息不进入消息队列。回调函数判断是WM_SETTEXT消息，于是将文本框的内存缓冲区替换为szBuffer里面的字符串。在更换完后，回调函数会向对话框发送一个WM_COMMAND（EN_CHANGE）消息（同步），用来告诉对话框编辑控件中的文本已更改。然后线程立马跳转到对话框回调函数里面，处理这个消息。在处理完这个消息后，线程调用InvalidateRect函数来指定更改的文本框为无效区域。由于这里是单线程，线程在执行 Clock 循环时，没有进入消息循环，也没有机会调用 GetMessage/DispatchMessage，所以即使有无效区域，也不会触发绘制，窗口不会有任何变化。与此同时，新一轮的循环继续开始。

​ 当Clock函数执行完毕，线程执行到对话框消息循环里面，先处理在卡死阶段进行的操作（包括移动窗口、最小化、最大化）产生的消息。在这些优先级更高的消息被处理完后，消息循环空闲，系统判断无效区域存在，然后生成一个WM_PAINT消息放入消息队列并进行处理，重绘这些区域后，窗口将会更新。由于Clock函数里面的循环执行完后文本框中的文本是”0”，故重绘后文本框直接显示”0”，不会有动态变化过程。

多线程情况：

​ 在Win32里面，如果一个窗口的回调函数可以同时被多个线程使用，那么就需要加入大量互斥锁。所以Win32直接将窗口与线程绑定，即在某个线程里面创建的窗口，此窗口的消息只能在此线程里面处理，其他线程无法访问此窗口的回调函数。

​ 假设在线程1里面创建了一个窗口，现在线程2需要给此窗口发送同步消息，此时，由于线程2无法调用此窗口的回调函数，故系统会阻塞线程2，然后将此消息放到线程1的消息队列，等待线程1处理。当线程1处理完后，线程2才会恢复。目标线程如果卡死，发送方会一直阻塞，甚至造成死锁（比如两个线程互相 SendMessage）。

​ 在这三种终止线程的方法中，前面两个都属于线程自己终止，TerminateThread函数方法是唯一一个可以通过其他线程来终止本线程的方法。但是，这个函数不会释放堆栈，所以不到万不得已，不要轻易使用。

​ TerminateThread函数是异步调用，它会创建一个新的线程去完成结束目标线程的任务，并不会堵塞本线程。因此，在新线程执行结束任务时，本线程还会继续往下走，如果后续有操作需要在结束目标进程后才能执行的可能会出现错误。所以，一般TerminateThread函数不会单独使用，而是会与WaitForSingleObject函数结合使用。

​ 当线程关闭时会发出信号，释放已等待线程终止的任何其他线程。WaitForSingleObject函数的作用是阻塞本线程，直到目标线程发出终止信号。

二、标准控件与通用控件

标准控件：

是 Windows 最早版本（Windows 1.x, 2.x, 3.x）提供的基础控件。

常见以下类型：

  • BUTTON：按钮（包括普通按钮、复选框、单选按钮、分组框）
  • STATIC：静态文本、图标、矩形框、分隔线
  • EDIT：单行或多行文本编辑框
  • LISTBOX：列表框
  • COMBOBOX：组合框（下拉列表框）
  • SCROLLBAR：滚动条（也常用于窗口本身）

它们提供核心的交互功能（点击、选择、输入文本、简单列表），在应用程序启动时即可直接使用，主要通过父窗口接收 WM_COMMAND 通知消息（对于按钮、编辑框、列表框、组合框）。

通用控件：

随着 Windows 95 和 Windows NT 4.0 引入，微软提供了更现代、更丰富的控件，通用控件是对标准控件库的扩展。他们由 ComCtl32.dll 实现和管理。在创建前必须先初始化通用控件库！必须调用 InitCommonControlsEx 函数注册控件窗口类才能使用。

资源表概述

结构：

​ 资源表（Resource Table）是Windows的PE文件中用于存储非代码/非程序逻辑数据的核心结构，包括图标、对话框、字符串、位图、菜单等静态资源。其设计采用树形目录结构，确保资源的高效组织与访问。

​ 资源表是可选头数据目录表的第三个成员，IMAGE_DATA_DIRECTORY[2]里面存储着资源表的起始RVA。资源表并非采用简单的结构体结构或结构体数组结构，为了对资源进行更好的管理，资源表采用如下的树状结构：

每一级对应着不同的作用。其中：

  • 第一级：类型。资源被划分为了很多种类，例如图标、字符串、对话框、菜单、、、。这一级系统预定义了16种类型，都是使用ID来标识的。用户可使用大于16的ID或使用字符串来定义新类型。
  • 第二级：编号。这里使用字符串或者ID对资源进行更细致的划分，如具体某个图标的ID。
  • 第三级：代码页。这里使用语言/代码页来区分不同资源（如中英文资源）。这里的每一个目录项结构都唯一指向一个资源数据入口（结构体）。这一级系统也预定义了一些代码页，如简体中文0x804。这些预定义的代码页都是用ID来标识的。用户也可自定义，但一般不会这么整（因为字符串需手动解析）。
  • 叶子节点：资源数据入口（图中绿色部分）。里面储存着目标资源的RVA和大小。

IMAGE_DATA_DIRECTORY[2]结构体中存储的RVA指向第一级（也就是根节点）的位置。这三层目录的每一个节点都是由一个资源目录头（图中红色）和若干个资源目录项（图中黄色）组成。第三层的节点指向数据资源入口（图中绿色部分），这里存储资源位置和大小。

资源目录头：

其中，最后两个成员NumberOfNamedEntries和NumberOfIdEntries最为重要，这两者之和代表了接下来会有多少个目录项。

资源目录项：

​ 这个结构体由两个联合体构成，每个联合体占4个字节，一共占8个字节。

​ 对于第一个联合体，它由一个4字节结构体、4字节的Name和2字节的id组成。这个id一般不用。在4字节结构体中，NameOffset占低0~31位，NameIsString占第32位。NameIsString仅仅是用来判断的：

  • 当NameIsString==1时，第一个联合体的后31位是一个偏移，偏移基址为本节点起始位置，此偏移指向一个IMAGE_RESOURCE_DIR_STRING_U结构体，此结构体存储资源或资源类的名称。
  • 当NameIsString==0时，此联合体代表此资源类或资源的ID。

​ 第二个联合体与第一个联合体结构相似，他的DataIsDirectory也是用来判断的。

  • 当DataIsDirectory == 1，代表下一个节点还是正常节点，OffsetToDirectory表示下一个目录节点相对于根节点起始位置的偏移。
  • 当DataIsDirectory == 0，代表下一个节点是叶子节点，即OffsetToDirectory表示一个资源目录入口结构体相对于根节点起始位置的偏移。

由于资源目录表采用三级树状结构，故前两级节点的DataIsDirectory==1，而第三级节点的DataIsDirectory==0。
